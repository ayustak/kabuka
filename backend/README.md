# kabuka backend

日本株予測・売買シグナル kabuka のバックエンド。
チーム調査（J-Quants / 予測モデル / バックテスト / 批判役）の推奨に従い、
**まず ¥0 の無料データでファクターのαを検証**する段階から始める。

## セットアップ

```bash
# リポジトリ直下で
python3.12 -m venv .venv
.venv/bin/pip install -e backend          # pyproject の依存を導入
```

## 無料データ・ファクターバックテスト（一次検証）

```bash
cd backend
../.venv/bin/python -m app.ingestion.prices     # yfinanceで株価取得→parquetキャッシュ
../.venv/bin/python scripts/run_backtest.py      # 分位バックテスト実行
```

### データソース（無料スタック）
- **株価(配当・分割調整済)**: yfinance（`code.T`）。10年以上取得可。
- **ベンチマーク**: TOPIX連動ETF `1306.T`（対TOPIX超過αの基準）。
- **財務(value/quality)**: EDINET API v2（無料・要キー）。下記手順で有効化。

### value/quality（EDINET財務）の有効化手順
1. https://disclosure2.edinet-fsa.go.jp/ で無料アカウント作成 → APIキー発行
2. `cp .env.example .env` して `KABUKA_EDINET_KEY=...` を記入
3. 疎通＆抽出確認（パイロット: 直近20営業日・ユニバースの有報のみ）:
   ```bash
   ../.venv/bin/python -m app.ingestion.financials
   ```
   ※決算提出が集中する6月頃を含む期間でないと0件のこともある。抽出列が正しいか確認する。
4. 本収集（期間内を日次スキャン。時間がかかる）→ `backend/data/financials_pit.parquet` 生成
5. `run_backtest.py` を再実行すると value/quality と総合スコアが自動で評価対象に加わる

> 注意: EDINETの要素ID(elementID)は会社・年度で揺れるため、`financials.py` の
> `FIELD_CANDIDATES` は初回実取得後に実データを見て調整する前提（PIT結合は submit_date 基準）。

### 評価設計（批判役の指摘を反映）
- ルックアヘッド回避: 月末tのファクター → 翌月t+1リターンで評価（重複なし月次）。
- 取引コスト織込み: 分位入れ替え turnover に往復コストを控除（既定 片道20bps）。
- 指標: 月次IC / ICIR、分位ロングショート年率・シャープ・最大DD、対TOPIX超過α・勝率。

### 既知の制約（重要）
- ユニバースは**現構成銘柄のみ＝生存者バイアスあり**。数値は上振れ方向。
  有望なら J-Quants Standard 等で時点別構成銘柄(PIT)・廃止銘柄を補完して再検証する。
- 一次合格基準は「絶対20%/15%」ではなく**「対TOPIXαが偶然でなさそうか」**。

## 検証結果（2014–2024, 161銘柄, 片道20bps）

| factor | IC平均 | ICIR | LS年率 | LSシャープ | 対TOPIX超過(ロング) |
|---|---|---|---|---|---|
| mom_12_1 | 0.015 | 0.23 | 1.9% | 0.20 | +5.9% |
| mom_6_1 | 0.020 | 0.35 | 3.5% | 0.31 | +5.0% |
| reversal_1m | 0.025 | 0.47 | 4.9% | 0.42 | +3.7% |
| low_vol | -0.014 | -0.23 | -9.3% | -0.59 | -1.1% |
| **composite**(mom_6_1+reversal) | **0.031** | **0.66** | **6.1%** | **0.56** | +3.7% |

### value/quality 追加後（EDINET財務, 2016–2024, 102ヶ月）

| factor | IC平均 | ICIR | LS年率 | LSシャープ | 対TOPIX超過 | 勝率 |
|---|---|---|---|---|---|---|
| **value_bp**(割安 B/P) | **0.031** | **0.80** | **11.7%** | **1.16** | **+11.6%** | **71.6%** |
| value_ep(益回り E/P) | 0.018 | 0.57 | 2.1% | 0.28 | +7.5% | 58.8% |
| quality_roe | -0.005 | -0.13 | -2.1% | -0.18 | +5.6% | 59.8% |
| quality_margin | 0.002 | 0.06 | -3.0% | -0.24 | +4.5% | 57.8% |
| quality_equity_ratio | -0.004 | -0.08 | -2.2% | -0.09 | +5.2% | 63.7% |
| value_quality(合成) | 0.015 | 0.42 | 0.7% | 0.13 | +5.0% | 64.7% |

**最大の発見**: **バリュー(B/P)が突出**（ICIR 0.80, LSシャープ 1.16, 対TOPIX +11.6%/年, 勝率72%）。
一方クオリティ系(ROE/利益率/自己資本比率)はこの大型株ユニバースでは LS が弱い〜マイナス。
→ 批判役の「日本株はモメンタムでなく**value**が効く」を実データで裏付け。

**統計的有意性 (Deflated Sharpe Ratio)**: 価格のみでは最良composite でも DSR=0.53 だったが、
value_bp 追加後は **DSR=0.885**（11ファクター試行で多重検定補正）。0.53→0.885 と大きく改善したが、
**まだ0.95には届かず**「偶然を完全には否定できない」水準。

**示唆**:
- **バリュー(B/P)が最強**。日本株のファクター構造（valueが効きmomentum/qualityは弱い）を実データで再現。
- 価格ファクターのみではモメンタムは弱く、合成しても DSR=0.53（非有意）。
- value_bp を加えると DSR=0.885 まで改善。バリュー軸が予測力の主柱。
- ただし **生存者バイアスで上振れ・税引前・期間102ヶ月・DSR<0.95**。絶対年率20%/15%の断定はまだ不可。

**コスト感度**: 片道0〜40bpsでLS年率はほぼ不変（ロングショートは両建てでコストが概ね相殺されるため）。
コストが効くのはロングオンリーの対TOPIX超過側。低回転の月次リバランスではコストは主因ではない。

**次の一手**: 本命の **value/quality** を入れる。履歴財務が要るため yfinance（現時点スナップショットのみ＝非PIT）では不可。
EDINET API（無料・要キー）で提出日付きの財務を取得して構築する（`app/ingestion/edinet.py` 雛形済、`.env.example` 参照）。
有望なら機能完成後に J-Quants Standard(¥3,300/月) でPIT・廃止銘柄を補完し本検証。
